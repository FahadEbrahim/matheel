# Matheel-Plagiarism-v1 input preparation

This directory records the pinned source recipe for Matheel's plagiarism track. `sources.json` contains immutable GitHub commit IDs, versioned archive URLs, exact archive sizes and SHA-256 hashes, published Zenodo MD5 checksums, and dataset provenance. It contains no source submissions.

Use Python 3.10–3.13 and install this checkout with its semantic backends before
running the scripts. The installed Matheel version is part of method identity:

```bash
python -m pip install -e ".[semantic]"
```

Prepare inputs in a cache outside this repository:

```bash
python scripts/prepare_plagiarism_benchmark.py \
  --cache-dir "$HOME/.cache/matheel/plagiarism-v1/archives" \
  --output-dir "$HOME/.cache/matheel/plagiarism-v1/prepared" \
  --download
```

Omit `--download` to require previously supplied archives. The expected archive layout is `<cache-dir>/<source-name>/<filename>` as declared in `sources.json`. Existing files are always verified before extraction; changed, incomplete, or mismatched archives cause preparation to fail. Downloads use bounded timeouts and temporary files. Archive extraction uses Matheel's traversal and size checks. Review and follow each dataset's access and license terms; SOCO14's source record does not declare a license in the metadata inspected for this recipe.

The script writes `prepared-manifest.json` for `freeze_benchmark_protocol`, plus `preparation-summary.json` containing semantic content fingerprints, counts, and all SOCO14 omissions. Local paths locate data; normalized records and source text define its content identity. Moving the cache does not change those fingerprints. Freezing and method evaluation are separate steps; preparation never scores methods or selects thresholds from labels.

## Defined task views

| View | Rows and source policy |
| --- | --- |
| ConPlag pair classification | All 911 source labels, using raw `version_1` Java files from each labeled pair's own directory. Preserve pair-specific copies because some repeated submission IDs have different source bytes across pair directories. BPlag's rewritten files and template-free `version_2` are excluded. |
| IRPlag pair classification | All 460 original/submission pairs from 467 Java files, preserving original/non-plagiarized/plagiarized directory labels. Retain the source's disputed negative labels and its documented caveat. |
| IPCA pair classification | All 270 comparisons generated by Matheel's P/NP and solution/variant filename policy, separately within the source course and assignment. There are 60 labeled source files. These pair labels are derived annotations, rather than a source-provided pair manifest. |
| Criminal Minds pair classification | All 350 original-to-plagiarized comparisons from ten original and 35 plagiarized Java submissions. Matching lineage is positive; different original lineage is negative. Multiple Java files belonging to one submission are concatenated in stable relative-path order. |
| Student Code Similarity pair classification | All 293 original pair labels over 174 Python source files from Kaggle dataset version 1. The source describes manually curated, simulated student scenarios. Derived feature tables are excluded. |
| IRPlag retrieval | All 355 queries with a positive annotation, against all seven original submissions. Exclude the 105 queries that have no positive qrel from this ranking task; pair classification still retains them. |
| SOCO14 judged-pool scenario retrieval | Ten nonempty language/scenario views, covering all 825 valid judged endpoints and 994 directed relevance records. C/C++ and Java are separate; every view contains one scenario. Each candidate pool contains exactly that view's valid judged endpoints, with self matches excluded. Source reuse judgments are undirected, so each pair contributes reciprocal relevance. |

The five pair views contain **2,284 labeled rows**. The complete manifest contains **16 task views**. Classification uses a predeclared threshold of 0.5; there is no threshold fitting or random subsampling in this preparation recipe. All supplied source labels are evaluation data, so this is not a claim of a newly constructed training/test split or unseen-dataset generalization. ConPlag's own training/test lists are not used to learn a threshold in this version.

Aggregate scores give equal weight to each declared task view, separately for classification and retrieval. Each of the five pair datasets contributes one fifth of a classification average. The ten SOCO14 scenario views together contribute ten elevenths of a retrieval average, and IRPlag contributes one eleventh. This is an equal-view average, not equal weighting of the two underlying retrieval sources; inspect per-view results alongside the aggregate.

SOCO14's original README requires separate languages and scenarios. The scoped Matheel ranking task uses its judged endpoints, rather than the full competition candidate corpus. It therefore measures performance within this declared candidate pool and must not be presented as a reproduction of the original competition. SOCO14 records source-code reuse; the plagiarism track preserves that ground-truth definition without inferring misconduct.

Exactly **47 updated SOCO14 qrel rows** reference absent files in the pinned archive: 44 C/C++ rows and three Java rows. Preparation records every omitted row and missing identifier. The C/C++ C2 and Java C1 views contain no valid positive judgments and are explicitly excluded. No replacement source files, invented negatives, or extra relevance labels are generated.

## Reproducibility checks

Offline tests use tiny synthetic archives and language/scenario fixtures. They verify archive mismatch rejection, raw ConPlag pair-copy selection, language identifier separation, reciprocal qrels, missing-file accounting, and unchanged semantic fingerprints after moving source directories:

```bash
python -m pytest -q tests/test_prepare_plagiarism_benchmark.py tests/test_datasets.py
```

Changing source bytes, row selection, candidate pools, relevance policy, or evaluation rules requires a newly frozen protocol identity. Public result artifacts should retain the protocol and configuration IDs and their full declared coverage. Keep archive caches, normalized submissions, model caches, and transient outputs outside Git.

## Run the declared methods

`methods.json` declares 29 configurations: the 27 built-in leaderboard presets,
with MiniLM-L6-v2 providing the three semantic preset variants, plus a trained
Model2Vec model and a PyLate multi-vector model. Every trained model has a pinned
Hub commit and an explicit backend. Semantic scoring uses CPU execution, a
256-token limit, and no chunking. Lexical methods use the source text without
preprocessing. These are declared baseline configurations, without test-label
parameter tuning.

```bash
python scripts/run_plagiarism_benchmark.py \
  --manifest "$HOME/.cache/matheel/plagiarism-v1/prepared/prepared-manifest.json" \
  --methods benchmarks/plagiarism-v1/methods.json \
  --output-dir "$HOME/.cache/matheel/plagiarism-v1/results" \
  --workers 3
```

Each method runs in a separate process, with one CPU thread and a 1,800-second
wall-clock budget from the frozen protocol. Slow methods receive null scores and
an explicit timeout; they do not receive a rank or an average of completed views.
The wall time includes model loading and evaluation, so it is not an isolated
scorer microbenchmark. Concurrent execution and host hardware affect timings.

Rerunning the command resumes checkpoints only after verifying the protocol,
method configuration, Matheel source fingerprint, and recorded score-file hashes.
`--retry-failed` repeats failed or incomplete method attempts. Changing scorer
source requires a new output directory. Scored CSVs contain identifiers, labels,
and scores; source submissions and local paths are excluded. Their SHA-256 index
is embedded in the portable result JSON so individual predictions can be audited.
Keep `protocol.local.json`, checkpoint method files, logs, and downloaded source
code private to the local run directory. `protocol.json` is the portable frozen
definition.

## Validate and publish completed results

Public results are maintained in one canonical directory,
[`gradio_app/benchmark_data/plagiarism-v1/`](../../gradio_app/benchmark_data/plagiarism-v1/),
so the repository and hosted Space use the same artifact. The result filename is
`matheel_plagiarism_v1.json`; matching CSV, HTML, detail, reproducibility, frozen
protocol, and score-index files accompany it. The directory is populated only
when the complete supervised run passes publication validation.

```bash
python scripts/publish_plagiarism_benchmark.py \
  --results-dir "$HOME/.cache/matheel/plagiarism-v1/results" \
  --score-zip "$HOME/.cache/matheel/plagiarism-v1/matheel-plagiarism-v1-scores.zip"
```

The helper checks the frozen protocol, all 29 declared methods, per-method source
fingerprints and wall times, complete finite-score candidate coverage, score CSV
hashes and permitted columns, matching report CSVs, and absence of machine-local
paths. Explicit timeout results are retained as unranked rows. No output is
changed if validation fails or the final merged result does not exist. The score
ZIP includes only indexed score files plus their index and portable protocol;
unindexed partial files, source submissions, logs, and checkpoints are excluded.
Keep this ZIP outside the repository and attach it to the GitHub release.

The [results guide](../../docs/plagiarism_results.md) records the publication status,
benchmark scope, and how to interpret the rankings. Offline declaration and
publication tests need no downloaded datasets or models:

```bash
python -m pytest -q tests/test_plagiarism_benchmark_declarations.py \
  tests/test_publish_plagiarism_benchmark.py
```
